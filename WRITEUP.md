# nexportal-gate — writeup

**What was built.** A readiness gate at two positions of NexPortal's operating model, on the surfaces the team already has — GitHub issues, a Projects board, the terminal, Claude Code:

| Position | Command | What it does |
|---|---|---|
| The door | `intake "<request>" --requester <name>` | A raw request becomes an issue with an `NX-INTAKE:` record: the learner outcome (or "none stated"), the urgency claim against its evidence, a duplicate check against open issues, a provisional size with confidence, questions routed to requester / design / engineering, and the message back — Thursday triage, what is in progress, what moves out if this jumps the queue. A duplicate creates nothing. |
| Before refinement | `gate <issue#>` | Tier 1, no model: the Definition-of-Ready form's shape — eight sections, ≥ 2 EARS criteria, a design link or an executable brief, a named requester, no open question riding the body. Tier 2, Claude Code headless with a JSON schema: steelman first, blocking vs non-blocking ambiguities with owners, untestable criteria with rewrites, hidden dependencies judged against a stated platform context, size with confidence, a ≤ 3-item refinement agenda, the message. The tool disposes of the verdict — `needs-info` iff a blocking trigger is present — and records both verdicts. |
| The wall | `flip <issue#> Ready` | One rule: no Ready unless the newest `NX-GATE:` record says `ready` **for the body as it is now** — a hash, not a timestamp. A refusal writes nothing and names the command that would fix it. The Claude Code hook locks the raw `gh project item-edit` door; `audit` names the door that cannot be locked (the web UI). |

Between the two, `draft <issue#>` fills the form from the intake record — a template, no model — because the PRD agent is not ours to build.

**Why this point.** The brief's pains, in its order: unclear requirements reaching engineers; wrong sizing because ambiguity surfaces mid-build; refinement bleeding into the sprint; and, layered on top, the CEO and Marketing arriving out of process. The PRD agent solves the first. Nothing stops the fourth, and nothing checks the drafts before an engineer sizes them — which is where the second and third are born. A gate at the door and a gate before refinement is the process the PRD agent lives inside; the one rule is what makes it enforced rather than described.

**What the live run showed.** Six pre-registered fixtures, verdicts frozen in git before the first run: 3/6 pass, and each miss is a reading, not a defect (`fixtures/results.md`). The one that matters: my own design brief — Part 0, Q4 — came back `needs-info` with five blocking gaps (grade-posted fires weekly per assignment, so a toast "at grade posted" fires every Friday; the source of the amounts; what "one tap" means on desktop; twelve referrals on a fixed-height card; on-load vs live delivery) and was resized from S to M. All five were real. Version 2 of the brief answers them and is what went to the board as issue #1: needs-info → v2 → ready → flipped. The gate caught the PM's own optimism; that is the job.

**Time saved — the shape, on stated assumptions.** Per ticket: refinement minutes spent re-deriving what it means — the agenda arrives written (assume 20 → 5). Per sprint: mid-build re-derivation events — the blocking ambiguities are named before sizing (assume 3 → 1). Per out-of-process request: the round-trips — one message says what is owed and by when (assume 4 → 1). Baseline is the first act of the 90 days; these are the numbers to measure, not a promise.

**Tool choice.** Claude Code headless (`claude -p --json-schema`) on the team's existing subscription — no SDK, no API key, no new vendor: the gate is one more invocation of a tool the team already runs (an assumption, stated; the brief lists Claude among the tools). Deterministic wherever it can be — Tier 1, the hash, the duplicate shortlist; the model only where judgement is needed — Tier 2; the human at the one-way door — the flip. Scaled down from the Yellow Robots factory (https://github.com/yellow-robots/factory): kept the patterns — the model proposes, the gate disposes; records on the trail; the board as the system of record; fail-closed to the human — and left out dispatch, the runner, epics, the ledger, the bench, the process model. Pre-registration and the results table are the honesty mechanism.

**How to verify.** Three postures. Nothing installed: read the trail — #1 (needs-info → v2 → ready → flipped), #2 (needs-info and a refused flip), #3 (intake → draft → Tier 1 fails on the open questions), #5 (the trap: Tier 1 passed, Tier 2 named the payments provider), and the board. Clone, no key: `python -m nexportal_gate fixtures --replay` reproduces the results table from the recorded responses; `pytest` runs 123 tests with no network. Clone with Claude Code: `fixtures` runs live; `claude --plugin-dir .` and ask it to run a raw `gh project item-edit` on the board — denied, with the reason (`hooks/DENIAL.md`).
